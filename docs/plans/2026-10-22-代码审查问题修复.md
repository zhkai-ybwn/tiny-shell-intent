# 代码审查问题修复实施记录

**目标：** 修复代码审查确认的五项问题，保留现有公开接口和建议后人工执行的交互方式。

**方案：** C# 与 Python 同步拒绝 PowerShell 弯引号，保留完整文件路径并在歧义时缺参；环境变量标识符独立校验和渲染；缓存保存和返回隔离副本；发布脚本检查原生构建退出码。

**技术栈：** .NET 8、Python 3.11+、PowerShell 7。

## 实施步骤

1. 为参数安全、完整路径、环境变量及缓存污染补充 C#／Python 回归用例，先确认旧实现失败。
2. 修改 `src/TinyShell.Core/Parameters/ParameterExtractor.cs` 和 `tiny_shell_intent/parameters.py`，使上述输入安全处理或保持不完整。
3. 修改 `IntentEngine.cs`、`QueryResult.cs` 和 Python 引擎，隔离缓存保存值与返回值。
4. 修改 `scripts/publish_module.ps1`，检查构建退出码；补充失败构建不会进入复制阶段的隔离验证。
5. 运行 C# 和 Python 全量回归，使用 PowerShell 语法树解析生成命令；成功构建模块并运行非物理按键场景验证。
6. 更新长期文档中的当前行为和验证证据。本次不安装到用户目录、不改用户 PROFILE、不执行候选命令、不进行 UI 自动化。

## 验收要求

- 弯引号输入不能成为额外 PowerShell 命令参数。
- `delete file C:\logs\data.tmp` 保留完整路径；有空格路径必须明确引用，歧义时不擅自截断。
- 环境变量建议通过 PowerShell 语法解析；无效名称不能渲染成完整命令。
- 修改首次结果及缓存命中结果的候选、参数字典或列表均不影响下一次查询。
- 非零构建退出码必须中止发布；成功链路仍可生成完整模块。
